## 0.2.0-beta.1 — 2026-11-20

### Changed

- **Messages say which ticket they're on; a requester's reply leaves in-progress and verifying tickets where they are** (`SupportMessage`, `createSupportDesk`, `SupportDesk`, `toSupportMessage`, `forRequesterMessage`)
  A message now carries its ticketId, so an application can check that a message belongs to the ticket in the URL before an edit. A requester's reply no longer takes a ticket out of in-progress (somebody is already on it) or out of verifying (a fix waits on their verdict, which only verdict() gives); from any other status it still reopens it.

## 0.2.0-beta.0 — 2026-11-20

### Added

- **Problem reports, fixes the requester verifies, attachments, diagnostics and recipients** (`ATTACHMENT_PURPOSES`, `MESSAGE_KINDS`, `RETEST_RESULTS`, `SupportAttachment`, `SupportDesk`, `SupportDiagnostic`, `SupportMessage`, `SupportRecipient`, `SupportTicket`, `TICKET_STATUSES`, `TicketChange`, `TicketListQuery`, `TicketSort`, `TicketStatus`, `createSupportDesk`, `forRequesterMessage`, `forRequesterTicket`, `supportAttachments`, `supportDiagnostics`, `supportDrizzleSchema`, `supportMessages`, `supportRecipients`, `supportTickets`, `toSupportMessage`, `toSupportTicket`, `AttachmentPurpose`, `MessageKind`, `MessageMeta`, `RetestResult`, `TicketReport`, `OpenTicketInput`, `ReplyInput`)
  Everything a problem-report desk does, added beside what was there (nothing renamed, every new column optional). Tickets can carry the bug form (report: expected, actual, steps, frequency), what they're about (about: type and id), a diagnostic note and internal notes for the agents, the fix (summary, commit, when), the retest result, who verified it, follow-up notes, and a soft-delete time. Two statuses: in-progress, and verifying (a fix is out, waiting for the requester). Messages have a kind (reply, note, fix, resolution, reject), a meta snapshot and an edited time: a fix waits in verifying with retest pending, a resolution closes as fixed, a reject reopens with what was said, and verdict() is the requester's word on a fix. New tables and calls: attachments (evidence or proof of a fix), diagnostics (a browser's capture, kept until it expires), recipients (who hears about new tickets, for all or one category); editMessage, getMessage, setNotes, remove (soft delete), findByReference (a guest's own ticket), unreadCount, categoryCounts; list() filters by category and several statuses, searches the requester's name, and sorts. A requester's view (forRequesterTicket, forRequesterMessage) leaves out internal notes, the diagnostic note and the fix's commit. Applications add the new columns and tables with a migration from the exported schema.

## 0.1.0-beta.2 — 2026-11-16

### Changed

- **markRead writes nothing when the ticket is already read, and returns whether it changed anything** (`createSupportDesk`, `SupportDesk`)
  markRead now updates only a ticket whose flag is still set and returns true when it cleared one, false when there was nothing to clear. Opening a read ticket is no longer a write, so a change feed or table trigger watching support_tickets (live updates) no longer sees a change on every read, which made a page that marks a ticket read when it loads refetch it forever.

## 0.1.0-beta.1 — 2026-11-16

### Added

- **Support tickets: a report with its context becomes a ticket, a threaded conversation with internal notes, and response-time analytics** (`createSupportDesk`, `toSupportTicket`, `supportTickets`, `supportMessages`, `supportEvents`, `supportDrizzleSchema`, `TICKET_STATUSES`, `TICKET_PRIORITIES`, `MESSAGE_AUTHORS`, `AnyPgDatabase`, `CreateSupportDeskOptions`, `OpenTicketInput`, `ReplyInput`, `SupportDesk`, `SupportEvent`, `SupportMessage`, `SupportTicket`, `TicketChange`, `TicketListQuery`, `MessageAuthor`, `TicketContext`, `TicketPriority`, `TicketStatus`)
  The first release: support_tickets, support_messages and support_events as Drizzle tables, and createSupportDesk over them: open (idempotent per submission), reply (agents' first public reply starts the response clock and waits on the requester; notes are agent-only; a requester's reply reopens), setStatus, setPriority, assign (each an event), get (with a requester view without notes or history), list with filters and paging, statusCounts, markRead and analytics (opened, resolved, unanswered, median first response and resolution, backlog by priority), with an onChange hook for emails and live signals.
